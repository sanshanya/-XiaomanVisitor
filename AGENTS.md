# XiaomanVisitor project rules

- Actual root: this repository, not DSH-Go. Read `docs/项目手册.md` first. It is the single current requirements, architecture, source-input and workflow reference; `docs/实机验收.md` lists author playtests. History/design documents are not current requirements. The version comes only from `package/XiaomanVisitor/manifest.xml`.
- Work on `develop/tavern`; `main` and `v*` tags retain the Workshop baseline. Preserve namespaces, item IDs and save keys across versions. Keep calendar days, actual encounter indices and future financial weeks separate. Append mod visitors to the native queue; never replace/reorder native story customers.
- Keep pure rules in `src/Domain`, native adapters/presentation/lifecycle in `src/Runtime`, generated catalogs in `src/Generated`. Domain may use JSON/BCL and stable identity constants, without Unity/native side effects. Do not add a service framework, speculative finance engine or another numerical model in these instructions.
- Use the manual's source-input table. Latest explicit author decisions win; v5.4 and its English companion own the fourteen chapters and letters, with specific later inputs overriding only their stated scope. Old weekly files supply uncovered mechanics/variants. Regenerate outputs; never patch generated catalogs alone or restore archived/Downloads prose as current text.
- Preserve approved Chinese/Japanese/English text, original artwork and matching audio unless changes are requested. `story/未相识台词.json` owns reviewed unacquainted variants; use `tools/story_variants.py`, never synthesize dialogue by removing names or punctuation. Review each variant with its base text.
- Runtime voice plays packaged recordings only. Generation and credentials stay outside the mod. The accepted spoken-tone/voice delta is complete: Ayano Japanese, 1.1x, original opening retained. Future paid TTS needs an explicit request; normal build/check/pack stays offline. Delivery-note edits alone do not justify rerecording.
- Use native APIs/rendering first. Preserve the verified SpriteRenderer/material/movement/foreground path; no UI portrait overlay or manual counter clipping. Scope camera changes to visible Xiaoman, retain departure ownership, restore state and respect new player settings. Release shared portrait resources after sprites/stages. Baseline: `baseline/native-render-0.0.3.3`; evidence: `docs/渲染问题复盘与性能取舍.md`. Pixel-area ratios are not FPS measurements or VRAM budgets.
- Every shared hook needs precise ownership and a native fallback. NEWS modifies a display copy, not world events; original articles have priority. Native customer, item, phone, dialogue and player-music behavior must survive leaving/disabling. Voice waits belong to `ModHelper`; read/load/disable cancels old waits rather than completing abandoned trade callbacks. Only source-tagged mod visitors may be withdrawn on disable.
- Preserve actual work/material/referral receipts, frozen values, item ownership and contributions. Keep recovery idempotent and fail closed on ambiguous identity/payment; do not guess refunds, redeliveries or debt. Current finite work orders are not a full NPC economy. Current W13-14 is the fixed leave ending, without implemented economic/rescue branching.
- Tavern uses the stable native `experimental_tavern` key, defaults on, has no activation warning and requires restart. Preserve saved choices/data. Gate registration, discovery, initialization, scene and actions together when off; Monday content remains independent. Current timing/gameplay/collection rules live only in the manual and their source configs.
- `tools/setup-dev.ps1` restores the environment. `tools/verify-dev.ps1` runs build/native/critical regression checks; use `-Full` for text/assets/delivery. Keep meaningful regression cases, not duplicate combinations or assertion-count targets. Native checks require actual local game assemblies and scanner; reject `Pending`, `Error`, `HardFlags` and undeclared capabilities. Keep `<Capabilities />` empty; do not add retiring background/network permissions to silence the scanner.
- Tests belong under `tests`; reports, caches and build products under `.dev`/`release`. Do not add per-version report copies to Git or repeat development chronology in the manual. Keep game assemblies/decompilations, saves, secrets and ZIPs out of Git; use LFS for media and retain source/font licenses.
- Build/check never installs or publishes. Normally completed and checked gameplay fixes should be installed before delivery, but the author's latest explicit package-only choice currently takes priority. On resuming installation, back up the previous install and verify the version and every installed file against the checked package. Ask the author to save/exit if the DLL is locked; never force-kill the game. Documentation-only work needs no reinstall.
- The author performs gameplay tests; do not launch/control the game unless explicitly requested. Report automated checks separately from real playtests, audio listening and measured performance. Do not promise zero bugs or compatibility with untested game/third-party versions.
- Workshop updates need an explicit author request. Inspect existing localized metadata first, use explicit languages, preserve subsequent author edits, update the existing item only and verify by reading it back. Do not publish or send external messages during ordinary cleanup.
