# XiaomanVisitor project rules

- Work in this repository on `develop/tavern`. Read `docs/项目手册.md` for current gameplay, source inputs and workflow; `docs/实机验收.md` owns manual playtests. The manifest owns the version; `main` and `v*` tags retain the Workshop baseline.
- The author's latest decisions take precedence. Preserve namespaces, item IDs, save keys, approved text, artwork and matching recordings. Regenerate catalogs from their source inputs; never edit generated output alone. Use the reviewed unacquainted variants rather than deleting names from base lines.
- Keep rules in `src/Domain`, native adapters/lifecycle/UI in `src/Runtime`, and catalogs in `src/Generated`. Prefer direct code, one owner per state and one validation at each boundary. Avoid redundant readback checks, duplicate state and service frameworks.
- Preserve actual transaction receipts and frozen values. Calendar days, encounters and financial weeks are different clocks. Ambiguous payment or ownership must pause the affected transaction; never guess refunds or repeat deliveries. Keep old-save migrations.
- Shared hooks must recognize their own objects and otherwise leave native behavior intact. Append visitors to the native queue. NEWS uses a display copy. Load/disable cancels abandoned callbacks; only source-tagged visitors may be withdrawn.
- Preserve native SpriteRenderer/material/movement/foreground rendering. Restore camera/music/UI state on exit and respect new player settings. Release owned sprites/stages before shared assets. Render evidence: `docs/渲染问题复盘与性能取舍.md` and `baseline/native-render-0.0.3.3`.
- Runtime plays packaged recordings only. Build/check/pack stays offline; paid TTS requires an explicit request. Retain Ayano Japanese at 1.1x and the approved original opening.
- Run `tools/verify-dev.ps1`; use `-Full` for delivery. Use actual local game assemblies/scanner; reject Error, Pending, HardFlags and undeclared capabilities. Keep `<Capabilities />` empty. Test behavior and meaningful failure paths, not assertion counts or duplicate implementation details.
- Keep tests in `tests`, local reports/caches/backups/releases in `.dev` or `release`, and media in Git LFS. Never commit game assemblies, decompilations, private saves, secrets or ZIPs. Retain source and font licenses.
- Install checked runtime changes with a verified backup and full file comparison, unless the author requests package-only. If the game locks the DLL, ask the author to save/exit; never force-close it. Do not launch/control the game without an explicit request. Report automated tests separately from playtests, listening and performance measurements.
- Publish only on an explicit request, to the existing item. Follow the manual's localized metadata preservation and readback workflow. Ordinary cleanup sends no external messages and does not publish.
