# 小满的十四个星期一｜第二周：另一盏灯

> 《深空当铺 × 小满酒馆》剧情与交互实施稿 **v4.1-W02**  
> 范围：第二周开业、第二次有效周一、首次夜访、酒馆基础交互、开业接待事件、第二封纸条与磁带、第二周其余日常  
> 状态：**中文剧情与交互方案可用于实现；日语为录音前审阅稿；六款酒价格为首测参数，不代表经济平衡定稿。**  
> 原则：无玩家口头对白、无旁白；日间沿用原生访客动作，夜间采用场景点击 + 小满气泡 + 选择菜单；不增加客人立绘、不制作每日随机事件。

## 0. 本周冻结的设计决定

| 维度 | 本周规则 |
|---|---|
| 开业时点 | **游戏第 8 天（第二个星期一）夜间**；不以第二次有效见面、成交、读信作为解锁条件 |
| 地图前置 | 第 1–2 天隐藏；第 3–7 天地图出现“商业街新店·装修中”，不可进入；第 8 天起改为“小满酒馆”并可进入 |
| 白天第二次会面 | 日用品、预算 200 CR，第二次会面后的次日投递纸条和 `intro`；交易不决定赠礼 |
| 点击小满 | 根菜单：**酒单／互动／只是看看**；互动子菜单：**闲聊／帮忙接待客人／返回** |
| 首夜事件 | “帮忙接待客人”是**一次性开业生活事件**，仅在开业周可首次完成，非经营 L1 项目，不产生直接收入或额外 Buff |
| 饮品 | 六款原有 Buff 酒全部列入酒单；选择、付款后**当场喝掉**，不进入背包，不可外带 |
| 购买上限 | 每游戏日最多在酒馆买并喝**一杯**；即使当晚重新外出／重入也不重置；小满以台词阻止第二杯 |
| 互动与喝酒 | **可在同一次夜访同时完成一次开业接待帮助和一杯酒**；帮助不额外消耗夜间外出次数，夜访本身仍遵守原生机会成本 |
| 其他场景交互 | 首次点击雨幕、磁带机各有一次台词；之后雨幕仅观察、磁带机可选已开放曲目 |
| 常规日常 | 周二至周日使用简短迎宾与少量闲聊；不强制每天来访，不做每日随机事件 |
| 尚未制作 | 经营账本正式周结算、L1–L4、融资/重组、关系等级、亲密互动、每日随机事件、客人可见立绘 |

**与旧方案的区别。** 旧“35 CR 无 Buff 普通杯”“整理取餐台”“每晚买酒与帮忙只能二选一”的试玩行为在正式第二周方案中退出。旧存档记录要迁移或保留历史，但不得直接当成本周的新进度。

## 1. 与第一周的连续性

- 第一周白天：小满只介绍“我叫小满。刚搬到附近，还有点认不清路”；发现玩家拥有磁带机。
- 第一周次日：纸条赠送 `title`。已确认其中一句采用“这首歌，是我在故乡下大雨的时候常听的。”
- 游戏第 3 天：NEWS 出现“商业街新店装修中”；夜间地图新地点显示为“装修中”，不开放。
- **第二周第 8 天**：日间小满正式告诉玩家自己开了酒馆；当夜地图开放。新闻、地图、到访三种时钟不能混为一个。

本周只有两次情感推进：白天收到邀请，夜晚发现店主小满的另一面。玩家不会被要求把这一晚变成经营培训。

## 3. 第二周周一夜间：初次进入场景

### 3.1 入场顺序

1. 原生夜间地图允许进入小满酒馆，扣除**一次原生夜访机会**；不额外免费发放外出次数。
2. 进入已设计的单幅酒馆画面。保留玩家背包入口、离开入口、小满气泡和角色口型。
3. 背景播放小满酒馆的曲目 `intro`（室内背景音乐，不等于向玩家发放磁带）。避免与角色语音互相盖过。
4. **首次进入**播放三句迎宾；演出结束进入自由点击态。没有强制教程、没有任务弹窗。
5. 玩家可以直接点击小满、左侧窗户雨幕、吧台后磁带机，或离开。

**场景交互位置（基于现有画面）：** 左侧大窗的模拟雨幕、吧台中央的小满、人物右侧的磁带机。使用原始场景坐标映射透明命中区域，不改变背景整体构图；不要强迫玩家点击装饰瓶子或食盒。

**购买事务约束**

1. 点击酒单先展示六种真实效果、持续时间、售价、玩家余额与“今日已饮用”状态。
2. 已饮用时仍可浏览酒单，但按购买或尝试再喝触发 `xm_tavern_drink_limit`；不进入第二次扣款。
3. 玩家确认所选酒后，检查 `game_day` 下是否已有已完成的酒馆饮用记录，以及余额是否足够。
4. 成功时扣取价格，**直接调用已有 Buff 的同一生效规则**并持久化消费记录；不产生 `GameItem`，不进入背包。
5. 交易失败、余额不足、UI 关闭不消耗饮酒次数；读档和重入不得再次结算同一笔购买。
6. 背包内原有的奖励酒、其他来源饮品不由此规则限制；这里的“一天一杯”指**酒馆柜台供应**。
7. 现版三日 Buff 从饮用当天起计，同类替换、不同类共存沿用既有规则；如果将来实现夜间行动效果，必须单独明确当晚生效时点。
8. 使用酒精版／果汁版时，调用原有酒精/成瘾处理的行为要核对，避免只是复用物品回调时错误触发酒精副作用。

### 4.3 互动 → 帮忙接待客人（第一晚重点）

## 8. 交互状态与存档建议

| 状态（建议语义键） | 作用 | 唯一性／时钟 |
|---|---|---|
| `tavern_opened` | 地图开放；由日历第 8 天及当前结局条件推导 | 按**游戏日**，与访问次数无关 |
| `w02_intro_seen` | 首次入店完整欢迎是否播过 | 每存档一次 |
| `w02_opening_reception_helped` | 开业接待帮助是否完成 | 每存档最多一次，可在第 8–14 天完成 |
| `tavern_drink_records[day]` | 酒馆当日已购买并喝的酒及价格 | **每游戏日最多一条**，与入场次数无关 |
| `tavern_entries_today` | 区分同夜重入 | 游戏日改变后重置；读档不能抹掉当日酒款 |
| `w02_rain_intro_seen` | 雨幕介绍是否播放 | 每存档一次 |
| `w02_tape_intro_seen` | 磁带机介绍是否播放 | 每存档一次 |
| `w02_chat_seen` | 避免重复刷首夜独白 | 不影响纸条、交易和主线推进 |
| `story_visit_index` | 当铺已经有效见面几次 | 与游戏日独立，沿用现有系统 |
| `visit_02_gift_mask` | 第二次纸条、磁带是否分别送达 | 沿用现有分部投递与恢复逻辑 |

**迁移：** 开发分支当前的 `tavern_v1_progress` 只允许每游戏日一条 `cup/pickup_point`，并有实验性普通杯、取餐台记录。升级时必须**保留历史数据或明确迁移为历史事件**，不能简单读取新 schema 失败就重置整个存档；旧 `pickup_point` 也不能变成新的开业接待完成标志。

**实际消费一致性：** 原生 `PayMoney` 与 ModData 保存不一定能天然原子提交。需要用稳定交易 ID 与提交状态，或利用已验证的原生交易回执恢复，避免“扣钱成功但日志失败后重新扣”以及“效果重复施加”。若无法完全原子化，优先失败关闭，再从待确认记录恢复，不可通过重新打开酒单直接补发效果。

**三套时钟：** `game_day` 控制地图、饮酒与开业事件窗口；`visit_index` 控制十四次当铺剧情；`last_entry_day / entries_today` 只控制迎宾与重入对白。不得用磁带领取次数推算开业日，也不得用到访次数代替真实财周。
